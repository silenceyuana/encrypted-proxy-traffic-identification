\begin{abstract}
Encrypted proxy traffic is difficult to distinguish from other encrypted network workloads because payload inspection is unavailable. This paper evaluates a reproducible flow-level pipeline that uses 30 flow statistics for JA4Tor and 20 window statistics for MineShark and compares Random Forest (RF), support vector machine (SVM), and k-nearest neighbors (KNN) classifiers. On the original JA4Tor evaluation, RF reaches 92.12\% accuracy; a capture-disjoint MineShark split gives 97.27\% with SVM. Under a workload-shift experiment from NBMiner training captures to XMRig test captures, performance drops to 46.66\% for SVM, showing that source and workload dependence must be reported. We provide feature-importance analysis, an auditable data split, figures, scripts, and metadata for reproduction.
\end{abstract}
\begin{IEEEkeywords}
encrypted traffic, proxy detection, machine learning, network flows, reproducibility

\section{Introduction}
Encrypted tunnels protect content but also limit conventional payload-based inspection. Statistical flow features offer a practical alternative for traffic classification, yet reported accuracy can be inflated by random row splits, duplicated captures, or ambiguous labels. This study focuses on an auditable baseline for encrypted proxy traffic identification and explicitly separates within-dataset performance from capture-disjoint and workload-shift evaluation.

\section{Data Sources and Label Audit}
The experiments use two public sources. JA4Tor provides labeled flow records for Tor and non-Tor traffic. Its NonTor label is retained as provided and is not reinterpreted as ordinary HTTPS. MineShark contains labeled cryptocurrency-mining and proxy-related captures. In particular, the dataset label \texttt{ssr} denotes ShadowsocksR, while \texttt{v2ray} denotes VMess. The available public labels do not constitute a complete four-class benchmark covering Shadowsocks, VLESS, Trojan, and ordinary HTTPS; therefore, no such four-class claim is made here.


The official ISCXVPN2016 artifact provides OpenVPN/non-VPN and application labels, which do not establish Shadowsocks, VLESS, or Trojan labels~\cite{gil}. We therefore use documented artifacts from NESTTOR/JA4Tor and MineShark~\cite{nesttor,mineshark}; their experiments are not pooled. JA4Tor comprises NonTor, Tor, Tor-over-Shadowsocks, Tor-over-Trojan, and Tor-over-VMess. Training contains 20,000 flows (4,000 per class), the primary test contains 5,000 (1,000 per class), and the second file contains 5,024. The public files lack complete row-to-capture provenance, preventing independent verification of capture-disjointness. The second test file is used as supplied; its acquisition domain is not inferred.

MineShark contributes 103 ShadowsocksR, 41 Trojan, and 64 VMess capture-derived records, yielding 12,401 eligible windows before sampling. Its archive MD5 is \texttt{6c64268ec35414fc9f483a7a4ed43755}. The supplied normal.pcap lacks per-flow HTTPS ground truth and is not relabeled as ordinary HTTPS. Capture files are divided approximately 70/30 within each class before balanced window sampling. IPs, ports, pool names, and acquisition dates are excluded from classifier inputs.

\section{Methodology}
JA4Tor uses 30 statistics derived from packet lengths, directions, counts, byte totals, and inter-arrival times (IAT). MineShark uses 20 statistics from non-overlapping 60-second windows containing at least 12 frames. Examples include mean and standard deviation of forward and backward packet lengths, maximum packet lengths, total bytes, packet counts, IAT summaries, and the down/up byte or packet ratio. Non-finite values are treated as missing and median-imputed using training data only, and numeric features are standardized for SVM and KNN.

\subsection{Feature Definitions and Model Settings}
JA4Tor includes directional packet/byte counts, packet-length summaries, flow duration and rates, and flow and directional IAT means and extrema. MineShark includes frame-length mean, standard deviation, median, and 90th percentile; IAT mean, standard deviation, and 90th percentile; upstream frame fraction; downstream/upstream byte ratio; and direction-switching rate. For arrival times $t_i$, $\mathrm{IAT}_i=t_i-t_{i-1}$; for byte counts $B_d,B_u$, the directional byte ratio is $B_d/\max(B_u,1)$. MineShark frame lengths include link-layer overhead and possibly oversized offloaded frames, and must not be interpreted as pure TCP payload sizes. Client direction is inferred from private addresses in preprocessing; addresses are excluded from classifier inputs.

RF uses 200 trees, square-root feature sampling, minimum leaf size 2, and random seed 42. The RBF SVM uses $C=10$ and gamma=scale; KNN uses $k=7$. Imputation and standardization are fitted on training data only. No test-set tuning is performed. These classifiers represent ensemble trees, nonlinear margins, and distance learning~\cite{breiman,cortes,cover,pedregosa}. Accuracy is the fraction of correct predictions; class recall is $TP/(TP+FN)$, and macro recall averages class recalls. Balanced test classes make accuracy and macro recall equal in some results.

\section{Experimental Design and Reproducibility}
For JA4Tor, we report the original test split and the separately published second test file. For MineShark, the primary split is capture-disjoint: training and test captures do not overlap. We report accuracy, macro recall, and macro F1. All saved predictions were re-evaluated independently, and the resulting metrics matched the stored CSV values. JA4Tor input hashes and the MineShark archive checksum are recorded in the repository metadata.

\subsection{Workload Shift}
When NBMiner captures are used for training and XMRig captures for testing, RF, SVM, and KNN obtain 44.81\%, 46.66\%, and 55.34\% accuracy, respectively. This experiment uses 3,702 training and 1,899 test windows. RF, SVM, and KNN macro F1 are 46.08\%, 42.87\%, and 54.55\%, respectively. SVM loses 50.61 percentage points relative to capture-disjoint evaluation. KNN superiority is limited to this fixed setting. This degradation indicates that workload and capture conditions can dominate the apparent decision boundary.

\subsection{Feature Importance}
The RF mean-decrease-in-impurity ranking identifies the following leading features on JA4Tor: Bwd Packet Length Max (8.19\%), Fwd Packet Length Std (6.97\%), and Down/Up Ratio (6.79\%), followed by additional length and IAT statistics. These features describe directional burst size and asymmetry, giving an interpretable indication of what the classifier uses. The identical RF configuration was refitted on 20,000 training flows and reproduced 92.12\% test accuracy. The top ten account for 57.18\% of importance. MDI can favor continuous or high-cardinality variables, while correlated variables share importance; the ranking is neither causal nor guaranteed stable across networks.

\section{Discussion and Limitations}
The results support statistical flow classification as a useful baseline, but they also show why split design matters. A random row split can benefit from correlated flows from the same capture, while capture-disjoint and workload-shift tests are more demanding. The public sources do not provide complete and consistent labels for all proxy families requested in a four-class taxonomy. Consequently, the findings should be interpreted as benchmark-specific evidence rather than universal protocol identification.

Proxy and application behavior, network path, server, capture year, client implementation, and TLS transport can confound statistical fingerprints~\cite{xue}. Future four-class evaluation should use matched browsing tasks, multiple independent nodes and capture rounds, saved PCAP hashes and protocol configurations, and node/run-disjoint partitions. Unknown proxies and padding/multiplexing should also be tested.
\section{Conclusion}
We presented an IEEE-style, reproducible pipeline for encrypted proxy traffic classification using 30 flow statistics and three classical classifiers. RF performs strongly on the original JA4Tor split, SVM performs best on the capture-disjoint MineShark split, and all methods degrade under workload shift. Feature ranking and explicit label auditing improve interpretability and prevent overclaiming.

\section{Reproduction Instructions}
The recorded environment is Python 3.12 and scikit-learn 1.9.1. The repository scripts \texttt{run\_ja4tor\_baseline.py}, \texttt{run\_mineshark\_proxy\_baseline.py}, and \texttt{run\_mineshark\_workload\_shift.py} reproduce the three experiments. \texttt{plot\_workload\_shift.py} generates the comparison plot, and \texttt{analyze\_feature\_importance.py} regenerates feature rankings and the methodology figure. Run each with Python from the project root using the \texttt{scripts/} prefix. Experiment manifests and capture-split CSVs record versions, hashes, feature definitions, and partitions. Original third-party data are downloaded separately; raw archives are not redistributed. Data sources: \url{https://github.com/das-lab/JA4Tor} and \url{https://zenodo.org/records/13624058}.
